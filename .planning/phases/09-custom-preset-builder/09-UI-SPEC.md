## Copywriting Contract

| Element | Copy |
|---------|------|
| **Builder Entry Button** | `+` (single character, always visible in preset row after built-in preset buttons) |
| **Dialog Title (Create)** | `New Preset` (or "Create Custom Preset") |
| **Dialog Title (Edit)** | `Edit Preset` (or "Edit [Preset Name]") |
| **Form Label: Preset Name** | `Preset Name` (text input placeholder: "e.g. My Morning Routine") |
| **Form Label: Phase Row** | Phase type name only: `Inhale`, `Hold`, `Exhale`, `Hold2` |
| **Form Label: Duration Input** | Duration in seconds: `Secs` or `Duration (s)` |
| **Validation Error: Empty Name** | `Preset name cannot be empty` (inline flash, red highlight on input) |
| **Validation Error: Too Few Phases** | `Select at least 2 phases` (inline flash message below phase checkboxes) |
| **Primary CTA** | `Save Preset` (button label) |
| **Secondary CTA** | `Cancel` (button label, closes dialog without saving) |
| **Destructive CTA** | First click: `Delete`; Second click: `Confirm Delete` (button changes label after first click, turns red) |
| **Delete Confirmation (body)** | `Are you sure? This action cannot be undone.` (optional inline text below Delete button) |
| **Save Success Feedback** | `Preset saved!` (flash message or silent success — confirm with planner) |
| **Fallback on Delete Active Preset** | App falls back to "Relax" (first built-in preset); no confirmation dialog needed — inline delete confirmation within Edit dialog is sufficient (D-08) |

**Notes:**
- Preset name input uses pattern from duration input error flash (Phase 3/v0.5).
- Error messages appear inline below the problematic field (matching `.durInput.error` pattern).
- Delete confirmation uses two-step button-label change (first click: "Delete" → second click: "Confirm Delete") — no second native `<dialog>` (D-07).
- Success feedback can be silent or a brief flash; confirm with planner in PLAN phase.
- All copy is user-facing text; do not hardcode in JS — keep in CONFIG UI object per CLAUDE.md convention.

## Component Specifications

### Builder Dialog

**HTML Structure (outline):**
```html
<dialog id="presetBuilderDialog">
  <form method="dialog">
    <h2>New Preset</h2>
    <!-- Preset name input -->
    <label>Preset Name</label>
    <input type="text" id="presetNameInput" ... />
    <!-- Phase rows: 4 rows for Inhale, Hold, Exhale, Hold2 -->
    <div id="phaseRows">
      <div class="phaseRow">
        <input type="checkbox" id="inhale-active" ... />
        <label for="inhale-active">Inhale</label>
        <input type="number" id="inhale-duration" min="1" max="300" ... />
        <span class="durUnit">s</span>
      </div>
      <!-- Repeat for Hold, Exhale, Hold2 -->
    </div>
    <!-- Buttons -->
    <div class="dialogButtons">
      <button id="presetSaveBtn" type="submit">Save Preset</button>
      <button id="presetCancelBtn" type="button">Cancel</button>
      <!-- Delete button appears only in Edit mode -->
      <button id="presetDeleteBtn" type="button" style="display:none;">Delete</button>
    </div>
  </form>
</dialog>
```

**Styling:**
- Dialog container: `border: 1px solid var(--panelBorder); border-radius: 12px; background: var(--panelBg); padding: 20px 22px;`
- Backdrop: `background: rgba(0,0,0,0.85);` (from --overlayBg)
- Title: `font-size: clamp(13px, 1.75vw + 9px, 17px); letter-spacing: 0.08em; text-transform: uppercase; color: var(--panelTitle);`
- Form label: `font-size: clamp(10px, 1vw + 7px, 12px); text-transform: uppercase; color: var(--panelSubtext);`
- Text input (preset name): `width: 100%; padding: 8px; background: var(--card); border: 1px solid var(--accentSoft); border-radius: 8px; color: var(--text);`
- Checkbox + label: flex row, `gap: 8px`, vertically centered
- Duration input: `width: 50px; padding: 4px; background: var(--card); border: 1px solid var(--accentSoft); border-radius: 6px; text-align: center;` (matches `.durInput` from index.html)
- Phase row container: `display: flex; gap: 8px; align-items: center; margin-bottom: 12px;`

**Behavior:**
- Form validation on submit (not on input): check name non-empty AND ≥2 active phases (D-04)
- On validation error: flash red background on invalid field (inherit `.durInput.error` animation: 400ms red tint)
- On save: call `saveCustomPresets()` function, close dialog, update preset selector UI
- On cancel / ESC / backdrop click: close dialog without saving
- Delete button: only visible in Edit mode; first click changes label to "Confirm Delete" and turns red; second click deletes preset and closes dialog

### Preset Selector Row Extension

**HTML:**
- Insert "+" button after the three built-in preset buttons (Relax, Box, 4-7-8)
- Add custom preset buttons dynamically via `renderCustomPresets()` function
- Each custom button: `<button class="presetBtn" data-preset="custom-<timestamp>" ...>Custom Name</button>`

**Styling:**
- "+" button: `font-size: clamp(13px, 1.75vw + 9px, 17px); padding: 8px 16px; border-radius: 20px; border: 1px solid var(--accentSoft); background: var(--card); color: var(--textSoft);` (matches existing `.presetBtn`)
- Hover: `background: var(--cardHover); color: var(--text);`
- Active: `border-color: var(--accent); color: var(--accent);`
- Custom preset button edit icon (desktop only):
  - Add hidden `<span class="editIcon">✎</span>` inside custom preset button
  - CSS: `opacity: 0; transition: opacity 80ms; position: absolute; margin-left: 4px;` (or inline)
  - On `.presetBtn:hover .editIcon`: `opacity: 1;`
  - Guard with `@media (hover: hover) and (pointer: fine)` (D-05)
- Custom preset button long-press (mobile): CSS scale feedback `transform: scale(0.97);` on `:active` state

**Behavior:**
- "+" button click: open builder dialog in "Create" mode (empty form)
- Custom preset button click: select preset, load phases/durations, hide duration sliders section (D-15)
- Custom preset button hover (desktop): reveal edit icon; click icon opens Edit dialog pre-filled with current preset data
- Custom preset button long-press (mobile): open Edit dialog; `touchstart` + `setTimeout(300ms)`, cancel on `touchmove` or `touchend` before 300ms

### Duration Inputs Section

**Behavior:**
- Hide or disable `#durationInputs` section when active preset is custom (D-15)
- When custom preset is active: `style.display = 'none'` or `aria-hidden="true"` + `disabled` on all inputs
- When built-in preset is active: restore normal visibility

## Data Structure & Persistence

**localStorage Key:**
- `CUSTOM_PRESETS_KEY` constant (alongside `STORAGE_KEY` and `HISTORY_KEY` in CONFIG section)

**Custom Preset Object Schema:**
```javascript
{
  id: "custom-1722456789123",  // "custom-" + timestamp, stable key for activePresetKey
  name: "My Preset",
  phases: [
    { type: "Inhale", durationSec: 5, active: true },
    { type: "Hold",   durationSec: 3, active: false },
    { type: "Exhale", durationSec: 7, active: true },
    { type: "Hold2",  durationSec: 0, active: false }
  ]
}
```

**Storage Format:**
- Array of custom preset objects stored as JSON string in localStorage under `CUSTOM_PRESETS_KEY`
- Load on init: `loadCustomPresets()` → parse JSON, handle QuotaExceededError silently (Phase 3/v0.5 pattern)
- Save on create/edit/delete: `saveCustomPresets()` → serialize to JSON, store (Phase 3/v0.5 error handling pattern)

**Integration Points:**
- `activePresetKey` global: custom preset IDs become valid values (e.g., `"custom-1722456789123"`)
- `activePhases` initialization: when `activePresetKey` is custom, build from custom preset phases (apply type→breathR/theme/cue lookup at runtime, D-09/D-10/D-11)
- `saveHistory()`: preset name stored as string (no change needed) — if preset is renamed/deleted later, history retains original name (D-14)

## Keyboard & Accessibility

**Keyboard Navigation (Phase 8 compliance):**
- All form inputs reachable via Tab / Shift+Tab
- Dialog focus trap handled natively by `<dialog>` element
- Submit form: Enter key (native form behavior)
- Cancel/Close: ESC key or Escape from button (native `<dialog>`)
- Focus returns to "+" button after dialog closes

**ARIA Attributes:**
- Dialog: `<dialog aria-label="Create Custom Preset">`
- Form labels: use `<label for="inputId">` semantics (standard HTML)
- Checkboxes: `<input type="checkbox" id="phase-type-active" aria-label="Activate [Phase] phase">`
- Error messages: optional `aria-live="polite"` on error container (confirm with planner)

**Focus Visible (Phase 8):**
- All buttons, inputs, checkboxes respect `:focus-visible` outline from Phase 8
- Focus ring: 3:1 contrast minimum against adjacent background (Phase 8/A11Y-03)

## Responsive Design

| Breakpoint | Behavior |
|-----------|----------|
| **Desktop (600px+)** | Dialog centered on screen; edit icon visible on custom preset button hover; form fields have standard widths |
| **Tablet (480–600px)** | Dialog width 90vw max; form fields scale with clamp() |
| **Mobile (≤480px)** | Dialog width 90vw; form fields stack vertically if needed; long-press opens Edit dialog instead of hover icon |
| **Landscape (height ≤500px)** | Dialog remains centered; compact form layout if height is very tight |

**Notes:**
- All typography uses `clamp()` — no hardcoded breakpoint changes needed.
- Dialog padding and spacing remain constant across all breakpoints.
