<task type="auto">
  <name>Fix G-09-4b/6b: Display custom preset user-given name instead of internal ID</name>
  <files>index.html</files>
  <action>
In updateModeIndicator() function (around line 1735), the code currently falls back to displaying activePresetKey directly when a preset name is not found in MODE_LABELS. For custom presets, this shows the internal ID (e.g., "custom-1785770816888") instead of the user-given name.

Replace the single-line assignment:

```javascript
if (el) el.textContent = MODE_LABELS[activePresetKey] || activePresetKey;
```

with:

```javascript
if (el) {
  if (activePresetKey in MODE_LABELS) {
    el.textContent = MODE_LABELS[activePresetKey];
  } else {
    const custom = customPresets.find(p => p.id === activePresetKey);
    el.textContent = custom ? custom.name : activePresetKey;
  }
}
```

This looks up the custom preset in the customPresets array and displays its .name property. If not found, falls back to the ID as a last resort.

Per G-09-4b/6b root cause: updateModeIndicator() at line 1735 falls back to raw activePresetKey for custom presets.
  </action>
  <verify>
    <automated>grep -A 6 "updateModeIndicator()" index.html | grep -c "customPresets.find"</automated>
  </verify>
  <done>The updateModeIndicator function now includes a customPresets.find() lookup for custom preset names. Grep finds exactly 1 match for the updated pattern.</done>
</task>

<task type="auto">
  <name>Fix G-09-4a/5a/6a/23: Correct active class toggling using activePresetKey comparison</name>
  <files>index.html</files>
  <action>
In the preset selector event handlers (lines 2964 and 2987), the code uses a stale button reference comparison (b === btn) to toggle the active class. After renderCustomPresets() recreates the DOM, the old button reference is no longer valid, causing the active class to be removed from newly created buttons or not applied correctly.

Find TWO occurrences of:
```javascript
document.querySelectorAll(".presetBtn").forEach(b => b.classList.toggle("active", b === btn));
```

Replace BOTH with:
```javascript
document.querySelectorAll(".presetBtn").forEach(b => b.classList.toggle("active", b.dataset.preset === activePresetKey));
```

This comparison uses the data attribute stored on each button (which persists across DOM rebuilds) instead of relying on object identity. It ensures only the button matching the currently active preset ID gets the active class.

Per G-09-4a/5a/6a/23 root cause: b === btn comparison uses stale button reference after DOM rebuild.
  </action>
  <verify>
    <automated>grep -c "b.dataset.preset === activePresetKey" index.html</automated>
  </verify>
  <done>Both occurrences of the active class toggle now use b.dataset.preset === activePresetKey. Grep finds exactly 3 matches for the updated comparison (2 fixed + 1 already correct at line 2231).</done>
</task>
