### Integration Warning: A11Y-01 — Cancel Button Focus Path

When the user clicks the Cancel button on the preset builder dialog (not Escape), focus lands on `settingsBtn` rather than `newPresetBtn`. Root cause: the cancel event handler sets focus to `newPresetBtn`, but the click handler then calls `closeSettings()` a second time, overwriting the focus to `settingsBtn`.

- **Escape key path:** Works correctly — focus returns to `newPresetBtn` ✓  
- **Cancel button path:** Focus returns to `settingsBtn` ⚠  
- **Impact:** Minor UX inconsistency; not a WCAG blocker (focus lands on a logical interactive element)  
- **Fix:** Remove duplicate `closeSettings()` from click handler — the cancel event fires first and handles teardown.
