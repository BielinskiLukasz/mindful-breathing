| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | `clamp(13px, 1.75vw + 9px, 17px)` | 400 | 1.4–1.8 (via clamp) |

**Font Weights Declared:** 2 weights only — 400 (regular) and 500 (medium/heading).

**ARIA Announcement Typography:** Phase label text (Inhale, Hold, Exhale, Hold 2) and running/stopped state are announced by screen readers via `aria-live="polite"` attribute. Font size/weight remain unchanged; announcement relies on DOM text content and aria-live region.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` — #111 (dark mode), cream (light mode) | Background, app surface |
| Secondary (30%) | `var(--card)` — #171717 (dark mode), cream+shade (light mode) | Buttons, control containers, input backgrounds |
| Accent (10%) | `var(--accent)` — #9aa0a6 (dark mode), #a0662e (light mode) | Ring progress, phase label, focus outline, active button border, all interactive states |
| Destructive | #e57373 (light red) | Stop button background (running state), error flash, delete actions |

**Accent reserved for (explicit list):**
- SVG ring progress stroke
- Phase label text (.phase)
- Countdown timer text (.time, .countdownNum)
- Active preset button border and text
- Primary Start/Pause button border and text (idle state)
- Focus outline (`:focus-visible` — all interactive elements)
- Completed session indicator
- Error flash background (low opacity)

**Primary Visual Focal Point:** Countdown timer (.time / .countdownNum) — the largest, most prominent element on the main screen, located in the center, and the primary target of user attention during an active session.

**Focus Outline Specifics:**
- All `:focus-visible` elements: `outline: 2px solid var(--accent); outline-offset: 3px`
- Applied to buttons, sliders, preset selectors, icon toggles, close buttons, and any focusable control
- Keyboard-only focus (not on mouse/touch click)
- Contrast verified: 3:1 minimum on both light and dark themes (warm gold on dark, bronze on light)

## Keyboard Navigation Contract

**Tab Order:** Follows DOM order as-is; no explicit `tabindex` values added unless element is not naturally focusable (D-06).

**Reachable Elements (in visual order):**
1. Preset buttons (Relax, Box, 4-7-8, and any custom presets — Phase 9)
2. Duration input sliders (Inhale, Hold, Exhale, Hold2 per active preset)
3. Start/Pause button (#toggleBtn)
4. Reset button (#resetBtn)
5. Corner icon buttons: Info (#infoBtn), Settings (#settingsBtn), Sound toggle, Vibration toggle, Fullscreen (#fullscreenBtn)
6. History summary element (togglable)
7. History action buttons: Export, Import, Clear, Pagination controls
8. When panel is open: all elements within that panel, then close button gets focus trap

**Global Keyboard Shortcuts (only when NO panel is open):**
- Space: Start/Pause
- R: Reset
- F: Fullscreen
- ESC: Closes open panel (any panel)

**Panel Keyboard Behavior:**
- Tab focus trapped inside panel (cycles from close button back to first focusable element)
- ESC closes panel and returns focus to the button that opened it
- Global shortcuts (Space, R, F) disabled while any panel is open (D-10)

## ARIA and Screen Reader Contract

| Element | ARIA Attribute(s) | Requirement |
|---------|------------------|-------------|
| #phaseEl | `aria-live="polite"` | Phase name changes and running/stopped state announced automatically (D-03, D-04) |
| All buttons | `aria-label` or visible text | Buttons with icons only must have aria-label; existing labels in codebase (e.g., "Toggle fullscreen", "Open settings") already present |
| Active preset | aria-pressed="true" (if <button>) or .active class | Selected preset visually distinct and announced if button role |
| Info panel | `role="dialog" aria-modal="true" aria-labelledby="infoTitle"` | Already present in codebase |
| Settings panel | `role="dialog" aria-modal="true" aria-labelledby="settingsTitle"` | Already present in codebase |
| CSV Import input | Hidden `<input type="file">` with `accept=".json,.csv"` (D-11) | Accept attribute updated; label/button that triggers it has aria-label |
| SVG icons | `aria-hidden="true"` on decorative SVGs | Prevents screen readers from announcing icon content; existing pattern in codebase |

**Announcement Events:**
- Phase name change (Inhale → Hold, etc.) — announced immediately
- Session started — announced when #toggleBtn pressed to start
- Session paused — announced when #toggleBtn pressed to pause
- CSV import result — announced via flash banner text (not aria-live; user triggers import action)

## CSV Import Visual & Interaction Contract

**Input Accept:** Updated single import button `<input accept=".json,.csv">`

**File Parsing:**
- Detect by file extension (`.csv` or `.json`)
- CSV format: strict match to app's own export format
  - Header row: `Date,Duration,Cycles` (or includes `Incomplete` column if present in current export)
  - Duration format: `M:SS` (e.g., `5:30` = 330 seconds = 330,000 milliseconds)
  - One session per row
  - Parse each row into `{ date: string, durationMs: number, cycles: number, incomplete?: boolean }`

**Validation:**
- Reject files that don't have expected header row
- Skip rows that don't parse as valid date/duration/cycles
- Silent catch on parse errors (no `throw` — D-16)

**Dedup Strategy:** Exact date string match (same as JSON import in Phase 5/v0.6). Do not overwrite existing sessions.

**Import Feedback:** Flash banner (non-blocking, 3–5 second dismiss)
- Success: "Imported {N} sessions, {M} skipped"
- No valid rows: "No valid sessions found in file"
- File read error: "Could not read file" (catch block)
