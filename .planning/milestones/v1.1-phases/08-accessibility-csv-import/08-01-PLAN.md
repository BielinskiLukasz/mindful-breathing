<assumption_delta_decision>
## Add-Alongside Decision for CSV Import

**Singular → Plural Transition:** Phase 8 adds CSV as a second import format alongside the existing JSON import. This IS a singular→plural transition (one import format → two).

**Decision: add-alongside (not promote)**
- The existing `importJson()` function remains unchanged; a new `importCsv()` function follows the exact same pattern (file reading, validation, dedup, feedback flash)
- Both functions share identical merge/dedup/validation contract; they both populate the same history array and use the same feedback mechanism
- No need to promote a general "import format dispatcher" abstraction—the format detection is a simple `.endsWith('.csv')` check in the file input handler
- If a third format (e.g. XML) were added in a future phase, that would be the trigger for creating a format dispatcher abstraction
- **Accepted Technical Debt:** The import handler will have a two-way branch (JSON vs CSV); keeping both functions parallel is intentional for code clarity and follows the existing pattern map

**Rationale:** Both formats serve the same user intent (restore session history from export), parse into the same data structure, and use identical persistence/dedup logic. Merging them into a single polymorphic function would add indirection without benefit; keeping them adjacent with clear routing is more maintainable for a single-file app.

<threat_model>

## Trust Boundaries

| Boundary | Description | Threat |
|----------|-------------|--------|
| User input → Parser | CSV file content from user upload | Malformed/oversized CSV |
| Focus manager → DOM | Focus movement during panel open/close | Focus escapes panel or leaves user without focusable target |
| Keyboard handler → Global state | Global shortcuts check `openPanelElement` state | State mismatch causes shortcuts to trigger when panel is open |
| Screen reader → aria-live | ARIA announcement of phase changes | Announcement frequency too high (every tick) or too noisy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-01 | Tampering | CSV file input (accept attribute) | high | mitigate | Strict CSV header validation in importCsv(); reject files without "Date,Duration,Cycles" header; silent catch on parse errors (no throw) |
| T-08-02 | Denial of Service | FileReader on large CSV | medium | mitigate | No explicit size limit in code; browser FileReader handles reasonable files; note: localStorage quota may reject oversized history. Accept as platform constraint. |
| T-08-03 | Information Disclosure | CSV import merges external data with existing history | low | accept | Dedup by exact date string match; existing sessions never overwritten. Imported data is user's own export; no external API involved. |
| T-08-04 | Repudiation | Focus management in panel | low | mitigate | Focus trap prevents accidental shortcut triggers; keyboard guard on Space/R/F disables global shortcuts while panel open. ESC always closes panel regardless of focus state. |
| T-08-05 | Elevation of Privilege | aria-live announcements | low | accept | aria-live on #phaseEl only; no privileged operations exposed via announcement. Screen reader receives read-only phase state. |
| T-08-06 | Denial of Service | aria-live announcement spam | medium | mitigate | Polite politeness level (not assertive) + announcement only on phase change and session start/stop (not every second). Per D-04, do NOT announce elapsed time on every tick. |
