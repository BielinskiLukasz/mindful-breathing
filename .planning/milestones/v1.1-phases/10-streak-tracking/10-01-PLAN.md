      * Longest streak is the longest consecutive run found while walking (calculated in the same pass)
      * Return { current, longest }

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → history array | Untrusted JSON parsed from localStorage; must validate date strings and incomplete flags |
| User input (goal cycles) | Already validated in DURATION_RANGE; streak computation is read-only |
| Session date normalization | ISO strings converted to local dates using toLocaleDateString('en-CA'); potential UTC/local mismatch if mishandled |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Tampering | computeStreak() input validation | medium | mitigate | Validate history array format (each entry has date: string) before processing; filter out invalid entries silently |
| T-10-02 | Information Disclosure | longestStreak exposure | low | accept | longestStreak is user-controlled data in localStorage; no sensitive info disclosed |
| T-10-03 | Denial of Service | computeStreak() on large history | low | mitigate | Computestreak() is O(n) where n ≤ 14 (history cap); negligible CPU cost |
| T-10-04 | Elevation of Privilege | localStorage access | low | accept | Single-user browser context; no multi-user escalation path |
| T-10-05 | Repudiation | Streak manipulation via console | low | accept | User can manually edit localStorage; this is expected in a client-only app |

</threat_model>
